生成テストが現在の変更を取りこぼす問題、プラン一覧の表示が不正な文書を空一覧として扱う問題、完了索引の古い参照先が検査されない問題を確認した。
それぞれを独立して検証できる三件の実装プランとして作成した。
いずれも未着手のbacklogであり、今回の成果は調査と計画作成までである。

## 調査の範囲と限界

対象リポジトリはtemp_project、調査時点のコミットは`f07616d02f8db6c6df55c2fa6dfedfd046e87c4f`である。
直近のGit履歴、完了済み計画、現在のbacklog一覧、生成テストと一覧表示の実装を確認した。
過去の計画が完了済みであることと、その計画が対象にしていた機能に現在も不足がないことは分けて判断した。

三つの問題は、一時ディレクトリ内の再現用リポジトリまたは文書で確認した。
既存の製品ファイルと過去の完了記録は変更していない。
今回の根拠はコミット済みの記録と再現結果であり、過去の全会話ログを読み直した調査ではない。
この調査用の実行記録には外部トランスクリプトとフックログを収集しておらず、その欠測をローカルのmanifestへ記録した。

過去に何回の検証が入力漏れの影響を受けたか、修正後に作業時間や費用がどれだけ変わるかは未確認である。
今回の再現だけから、過去の全検証が無効だったとは判断しない。

## 生成テストで確認したこと

[tests/smoke.sh](../../tests/smoke.sh)は、参照するコミットが指定されなければリポジトリを一時cloneし、手書きの一覧に載るファイルだけを上書きしてコミットする。
コピー対象とステージ対象に同じような長い一覧が二つある。
一覧にないファイルは、作業中の変更があってもclone時点の内容が残る。
異常な回答値を拒否する一部の試験も、準備済みの生成元ではなく元リポジトリのHEADを指定している。

再現では、一時cloneの`template/.project-agent-workflow/scripts/tool_command_context.py`へコメントを一行追加し、現行の生成元準備処理をそのまま実行した。
処理は終了コード0で完了したが、生成元のファイルは変更後のファイルと一致せず、元のコミットと一致した。
これは生成前の入力選択の不足を示す。
生成されたプログラムが実際に不具合を起こした回数までは示さない。

311では、生成テストへ渡すファイルの内容と実行属性を、Gitから列挙して一時コピーする処理を一つにまとめる。
対象はCopier設定、template以下、実行されるscripts以下に限る。
実行するテスト自体は減らさず、正常系と異常系が同じ生成元を使うようにする。
明示的にコミットを指定して過去の版を検査する経路は保持する。

実装時には、一覧から漏れていたファイルの変更、追加、削除、実行属性、空白を含むパスを試験する。
元リポジトリのHEAD、参照、インデックス、作業ファイルが変わらないことと、作業中の無視対象ログや範囲外の追加ファイルが取り込まれないことも確認する。
一時コピーを作る処理には保守が必要になるが、ファイル追加のたびに二つの一覧を直す必要はなくなる。
この変更はテンプレート開発側の試験資材に限定し、利用側へ配る新しい仕組みにはしない。

## 一覧表示で確認したこと

[一覧表示の実装](../../template/.project-agent-workflow/scripts/plan_overview.py)は、[既存の共通解析器](../../template/.project-agent-workflow/scripts/planlib.py)とは別にactive一覧を解析している。
空一覧を表す行を見つけると後続の内容を検査せず、内容が空のファイルも空一覧として扱う。

一時ディレクトリに`docs/plan/plan.md`を置き、次のコマンドを実行した。

```sh
python3 scripts/render-plan-overview.py --root <一時ディレクトリ> --json
```

| 入力 | 現在の表示コマンド | 共通解析器 |
| --- | --- | --- |
| 規定どおりの空一覧 | 終了コード0、`[]` | 受理 |
| 空一覧の後ろに文章を追記 | 終了コード0、`[]` | 拒否 |
| 内容が空のファイル | 終了コード0、`[]` | 拒否 |
| 列見出しだけでデータ行がない文書 | 終了コード1 | 拒否 |

後ろに文章を追記したケースの入力は、次のとおりである。

```text
# Active Plan

No active development items.
unknown content
```

310では共通解析器を表示側から呼び、二重に管理していた解析規則をなくす。
rootと生成プロジェクトの両方の入口で、同じ入力に対する判定結果を試験する。
表示は任意のままにし、古い説明文を理由にコミットや実装を止める条件は追加しない。
規定を採用していない利用側の文書も、自動では書き換えない。
不正入力を以前は表示できた利用者には診断が返るようになるため、その違いも回帰試験で明示する。

## 完了記録の索引で確認したこと

[完了記録の索引](checked.md)には244行あり、そのうち001から023までの23行が存在しないパスを指していた。
各行のファイル名に対応する実体は、いずれも`docs/plan/checked/2026/07/01-15/`以下に一件ずつ存在する。
不足しているのは完了記録そのものではなく、完了記録の索引が指す保存先の更新である。

生成側の`lint_checked_index`だけをrootに対して呼ぶと、最初の001の行で終了コード1となり、`checked index points to missing file`が返る。
一方、rootの`check-root-agent-policy.py`は成功し、必須lintにもこの索引検査を呼ぶ処理はない。
生成プロジェクト側の検査を持っていても、テンプレートを開発するリポジトリ自身に適用していない箇所が残っていた。
この確認では、生成側のプラン検査全体をrootへ適用した結果を根拠にはしていない。

312では、生成側にある索引の参照先検査を共通関数へ移し、rootの既存の必須検査からも呼ぶ。
23行のパスだけを実在する日付付きパスへ修正し、番号、順序、完了記録の本文は保持する。
保存先の不存在、重複、番号の不一致、保存範囲外のパスを試験し、古い記録へ新しいマニフェスト項目を要求しないことも確認する。
この検査は完了記録の実体を扱うものであり、任意の説明文やbacklog表示の更新を要求するものではない。

独立レビューでは、既存の検査が文字列上の保存先だけを比べている点も指摘された。
親セッションの一時ファイルで確認すると、`..`を含むパスとシンボリックリンクで保存範囲外を指していても、既存の検査は終了コード0となった。
312にはパスの正規化、シンボリックリンクの拒否、解決後の保存先の確認を追記し、この二つの経路も試験対象にした。

## 文書の更新と確認方法

backlogのREADMEには、以前の九件を未着手として扱う説明と、移動前のリンクが残っていた。
今回の作成に合わせて現状の説明へ更新し、現在のbacklogは既存コマンドで生成した一覧を載せた。
過去の状態はGit履歴とcheckedまたはreplannedの記録で追跡できる。
この計画と調査記録はtemp_project固有の文書なので、templateへ複製しない。
310と312の実装範囲にはrootと生成側の対応箇所を含め、311の試験資材は配布対象にしないと明記した。

各プランの完了条件は、実装時に追加して登録する回帰試験へ対応づけた。
既存のテストコマンドを今実行しただけで、未実装の条件が成立したとは扱わない。
実装後は再現例の解消、現在の入力の保持、元ファイルの不変性、両入口の結果一致を確認し、必須のlintとsmokeも行う。

詳細な選択肢の比較と再現結果は、ローカルの`.agent-artifacts/development-improvements-20260912/`へ保存した。
この記録と関連する検証出力は`.agent-logs/development-improvements-20260912/`から追跡できる。
生ログや大きな資材はコミットに含めない。
