## Problem

The published v1.0.0 migration exits successfully while a realistic customized repository is left with four unmerged files, deleted legacy policy and helper paths, and a failed repository adoption check.

Copier smart diff replays downstream edits made to pre-namespace generated files onto new host bridges, so the migration cannot infer a safe semantic merge from path ownership alone.

## Goal

Provide a fail-closed pre-v1 boundary and a separate one-time recopy-based adoption operation that preserves existing project behavior before normal Copier updates resume.

## Concrete Boundaries

- Existing tracked files at legacy agent-policy, helper-script, skill, hook, and helper-agent paths in a pre-v1 generated repository.
- Files generated under .project-agent-workflow plus stable host discovery bridges generated by the v1 template.
- A repository-clean operation that backs up legacy paths, runs Copier recopy at the selected v1-or-newer tag, preserves project-owned paths, installs stable hook bridges, and verifies Git state.
- A normal copier update executed only after .copier-answers.yml records a v1-or-newer template and .project-agent-workflow exists.
- An attempted copier update that crosses from a v0 template directly through the v1.0.0 migration using Copier smart diff.

## Decisions

- Keep the published v1.0.0 tag immutable and prepare a later minor release for the corrected contract.
- Reject direct v0-to-v1 smart-diff migration before it changes the destination.
- Use a dedicated recopy-based adoption command that copies legacy files to the migration backup, preserves extra project paths, installs the managed namespace, and checks Git state.
- Preserve customized Codex agent definitions as project-owned seeds, while replacing legacy hook implementations with backed-up stable bridges.
- Retire or bridge only exact-digest legacy optional files according to the new mode, record the action in the manifest, and preserve modified variants for review.
- Treat downstream validation assertions that hard-code an old Copier tag as project-owned follow-up work and report their exact paths instead of rewriting them generically.
