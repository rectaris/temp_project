## 実装前の設計確認と開発手順の改善

[342：ツールの挙動とシステムの制約を実装前に照合する](342-check-tool-and-system-assumptions-before-implementation.md)では、既存の設計確認手順と実装ガイドを具体化する。
設計を成立させなくなる未確認事項を小さな試行で確かめ、指摘が設計の前提を崩した場合は、個別修正の前に設計へ戻る。
見落としは既存の改善記録へ残し、運用、規約、回帰テストのどこを直すべきかを分けて判断する。
既存の評価手順で正常例と反例を比較し、構造検査の通過をエージェントの行動改善の証明とは扱わない。

342は独立した未着手の実装計画であり、364の完了を前提としない。
364の停止記録、レビュー上限、受け入れ条件を変更する計画でもない。

## レビュー証拠の経路

段階レビューは、レビューア側の実行記録が対象の包を最初の入力として観測したことを示さなければ採用できない。
この記録を取得できなかったため、376は一度中断した。
次の3件で取得と検査の経路を整え、376では実際の初回入力とツール呼び出しを観測したレビューを採用した。

1. [333：レビュー包の到着の記録](../checked/2026/09/01-15/333-observe-review-packet-at-turn-zero.md)（完了）
   レビューア自身のプロンプトフックが、送信された最初のプロンプトから包のダイジェストを算出して記録する。
   プロンプト本文は保存せず、`scripts/plan-execution-state.py`が持つ採用条件は変えない。
2. [335：レビューアのツール呼び出しの要求](../checked/2026/09/01-15/335-require-observed-reviewer-tool-calls.md)（完了）
   束ねた実行記録がツール呼び出しを1件も観測しない段階レビューを拒否する。
   376のレビュー担当が、ファイル参照0件で問題なしと応答した事例に対応する。
3. [344：着手前のレビュー経路の検査](../checked/2026/09/16-31/344-check-review-route-before-product-edits.md)（完了）
   実行が製品ファイルを変更する前に、試験用の実行記録で経路を検査する。
   333と335が導入する条件をそのまま検査するため、2件の完了後に開始する。

333の実装時だけは自身が導入する記録をまだ使えなかったため、旧来の`record --event-type parent_review`で1回だけレビューを記録した。
予備検査との結び付け、登録簿への登録、epochのレビュー予算が働かない点は、333の完了記録に残している。
この例外は後続プランに適用しない。

前提作業への参照は、`docs/plan/checked.md`から実在する完了記録に解決してから昇格する。
この確認は長らく人手で行ってきたが、377が context_files と integration_gates の分を検査に置き換えた。
