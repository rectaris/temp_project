## 現在のbacklog一覧

静的チェックの強化と、範囲を限定した自動修正を、次の順に実装する。
いずれも計画作成までの段階であり、実装には未着手である。

1. [364：Pythonのlintと限定した自動修正](364-enforce-bounded-python-lint.md)
   Ruffで未定義名などを検査し、自動修正は許可した規則と明示したファイルに限定する。
   試行で検出した13件の未定義名の診断を確認し、必要な修正を行う。
2. [365：検証用Pythonスクリプトの型検査](365-check-types-in-python-validation-tools.md)
   Pyrightで引数や戻り値の型を検査する。
   最初は3種類のスクリプトとテンプレート側の対応ファイルを対象にし、6ファイルすべてが解析されることを確認する。
3. [366：検証用Pythonスクリプトの整形](366-format-initial-python-validation-tools.md)
   同じ6ファイルにRuffのフォーマッターを適用し、整形漏れをローカルとCIで検査する。
   不具合修正とは別のコミットにし、構文木とコメントの保持、再実行で差分が出ないことを確認する。

既存の必須検証を保ち、生成済みプロジェクトの更新でも製品コードやプロジェクト所有の設定を保持することを各プランの完了条件に含める。
LSP接続、Python以外のツールの導入、全ファイルの一括整形は、この初期導入には含めない。
